# AGENTS.md

## Назначение проекта

`YaMusicSDK` — самостоятельная Kotlin/JVM-библиотека для работы с API Яндекс Музыки.

Проект использует `MarshalX/yandex-music-api` как проверенную основу знаний об API:
endpoint-адресах, параметрах запросов, моделях ответов, особенностях поведения и
результатах reverse engineering.

`YaMusicSDK` не является построчным или структурным портом Python SDK.

## Основные принципы реализации

- Публичный API должен следовать Kotlin-конвенциям, а не структуре Python-пакета.
- Асинхронные операции строятся вокруг Kotlin Coroutines и `suspend`.
- Использовать Kotlin null-safety и типизированные модели результатов.
- Не переносить Python-классы, методы и обёртки один к одному без необходимости.
- При расхождении Python-дизайна и идиоматичного Kotlin-дизайна сохранять сетевую
  семантику и ожидаемый результат API, но выбирать решение, естественное для Kotlin/JVM.
- Приоритеты: корректное поведение API, удобный Kotlin API и потребности приложения `Движ`.
- `JSONObject`, `JSONArray` и сырые транспортные ответы не должны появляться в публичном API.
- Публичные сетевые операции должны возвращать типизированный `YamResult<T>`.

## Источник истины по API

Оригинальный проект:

`https://github.com/MarshalX/yandex-music-api`

При реализации или проверке метода:

1. Найти соответствующий публичный метод и модель в оригинальной Python SDK.
2. Проверить endpoint и HTTP-метод.
3. Проверить query/form/body-параметры и заголовки.
4. Проверить формат и структуру ответа.
5. Сопоставить nullable-поля, значения по умолчанию и вложенные модели.
6. После этого спроектировать идиоматичный Kotlin-контракт.
7. Не воспроизводить Python-структуру и вспомогательные обёртки, если они не нужны
   для сетевого контракта или публичного API библиотеки.

Если README, документация Python SDK и фактическое поведение API расходятся,
приоритет имеет фактический сетевой контракт, подтверждённый исходниками
`MarshalX/yandex-music-api` и реальными ответами сервиса.

## Локальный клон оригинальной SDK

Для анализа рядом с проектом может использоваться локальный клон
`MarshalX/yandex-music-api`.

Путь задаётся в:

`local.properties`

Пример:

```properties
LOCAL_CLONE=C:\\path\\to\\yandex-music-api
```

`LOCAL_CLONE` используется только как ориентир для локальной разработки и
сравнения реализаций.

Python SDK не должна становиться зависимостью сборки `YaMusicSDK`.

При отсутствии клона:

```powershell
git clone https://github.com/MarshalX/yandex-music-api.git C:\path\to\yandex-music-api
```

## Основные точки входа проекта

- `YamApiClient.kt` — публичный высокоуровневый API клиента.
- `network/` — HTTP transport, декодирование ответов и `YamResult`.
- `auth/` — OAuth Device Flow.
- `account/` — аккаунт и статус пользователя.
- `likes/` — лайки и список понравившихся треков.
- `playlists/` — операции с плейлистами.
- `tracks/` — треки и playback telemetry.
- `search/` — поиск и поисковые подсказки.
- `rotor/` — «Моя волна» и rotor feedback.
- `download/` — download-info, прямые ссылки и бинарный аудиоконтент.
- `covers/` — загрузка обложек.
- `entities/` — публичные модели данных.

## Сетевой слой

Разделять:

- JSON API;
- бинарный контент;
- публичные модели библиотеки;
- транспортные детали.

Не протаскивать детали HTTP/JSON транспорта в публичный API.

Ошибки сети и API должны преобразовываться в типизированные ошибки `YamResult`,
например:

- Unauthorized;
- Timeout;
- NoInternet;
- Http;
- другие специализированные ошибки, когда это оправдано контрактом.

## Авторизация

OAuth Device Flow должен повторять сетевую семантику оригинальной SDK, но иметь
корутинный Kotlin API.

Корутинные операции авторизации должны штатно поддерживать cancellation.

Низкоуровневые операции Device Flow могут быть доступны отдельно, если это
необходимо для интеграции.

Хранение access token и refresh token является ответственностью вызывающего кода,
если отдельный механизм хранения явно не реализован библиотекой.

## Playback telemetry

Для обычного воспроизведения используется `/play-audio`.

При старте и завершении/прерывании воспроизведения необходимо сохранять один
`playId` для соответствующей сессии прослушивания и передавать актуальные:

- `totalPlayedSeconds`;
- `endPositionSeconds`;
- идентификаторы трека/альбома;
- источник воспроизведения;
- `playlistId`, только если трек действительно воспроизводится из плейлиста.

Для радио `/play-audio` используется вместе со специализированным Rotor feedback,
а не вместо него.

## Безопасность и логирование

Никогда не логировать:

- access token;
- refresh token;
- cookies;
- полный `Authorization` header;
- другие секретные значения авторизации.

При добавлении диагностического логирования редактировать или исключать
чувствительные заголовки и параметры.

## Совместимость с оригинальной SDK

Оригинальная Python SDK является reference implementation и источником знаний,
но не архитектурным шаблоном.

Не копировать код из `MarshalX/yandex-music-api` без необходимости.

Если код непосредственно используется или адаптируется, учитывать лицензию
LGPL-3.0 и сохранять необходимую атрибуцию источника.
